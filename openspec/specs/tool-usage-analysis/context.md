# Local tool observations

[Requirements](spec.md). Run uv run python scripts/analyze_tool_usage.py path/to/archive.jsonl path/to/archive.jsonl.gz. The CLI reads explicit files without loading application settings, a database or a provider. Gzip/JSONL, plain JSON websocket records and archived SSE text are recognized. The output contains tool names, observed call/results, explicit structured successes/errors and unknown outcomes, not payload text.

It recognizes function, custom-tool and computer protocols. It does not infer prompt quality or model correctness, score natural-language results, or measure per-tool tokens when the provider supplies only request-level usage. Failed/unmarked outputs remain unknown unless a structured error or success flag is recorded. Missing results and orphan results are exposed. Older archives may lack session identity: default correlation is request-scoped. When files have been independently restricted to exactly one conversation, --single-session permits correlation across request IDs. Do not use that flag on multi-session archives, since call IDs can repeat. Without identity, calls remain record-scoped rather than being incorrectly merged. Deduplication memory grows with unique identities; protocol traversal is capped at 12 nesting levels. Corrupted files produce a private nonzero I/O error.

Example: the same call appears in an upstream completed response and a later full resend. With session identity it counts once; an is_error=true result records an explicit tool error. A result containing the word error without a structured flag stays unknown. Function names themselves are reported, so review names before sharing a summary. Archive recording remains separately opt-in, and summaries cannot reconstruct absent results or encrypted contents.
