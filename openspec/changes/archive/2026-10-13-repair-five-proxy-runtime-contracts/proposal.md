## Why

Warm bridge turns still fall back to startup admission caps, and native Codex quota events expose a selected account instead of the visible pool. Five open registry rows need independent local evidence, including the already implemented HTTP timing, drain observation and scheduler shutdown contracts.

## What Changes

- Resolve one immutable dashboard admission snapshot before the warm bridge pending lock, for keyed and unkeyed sessions.
- Project or omit native quota events using the same pooled snapshot and API-key privacy policy as downstream headers, while retaining raw account ingestion.
- Independently verify existing HTTP phase provenance, nonblocking persistence ownership observation and bounded background-task shutdown.
- Update exactly UP-PR-2561, UP-PR-2308, UP-PR-2112, UP-ISSUE-2343 and UP-ISSUE-2505 with scoped evidence.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `proxy-admission-control`: warm reacquisition uses explicit dashboard caps outside the pending lock.
- `responses-api-compat`: native quota events describe the visible pool and omit unrepresented families.
- `api-keys`: stream quota telemetry follows the existing quota privacy policy.

## Impact

Bridge admission, HTTP/source SSE normalization, native WebSocket forwarding, focused tests and OpenSpec. No migration, setting, dependency, UI, default or deployment change. Existing dirty work is preserved. Local verification does not certify hosted CI, upstream merges, live clients or production.
