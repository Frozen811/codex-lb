# Routing ownership repair context

This package covers exactly UP-PR-2332, UP-PR-2469, UP-PR-2486, UP-PR-2458, and UP-PR-2001. Source metadata and all initial rows are saved in source-snapshot.json. Baseline dirty bytes are backed up outside the repository.

The newly missing behavior is not general ciphertext portability. A coded quota rejection before any visible output proves that this attempt did not execute, so it must not manufacture a dispatch owner for an otherwise eligible ciphertext-only body. The replacement may still reject ciphertext; the client receives that rejection and operators receive provenance without opaque content.

Example: an unanchored turn contains a retained compaction block and new plain user input. Account A returns usage_limit_reached before acceptance. Account B receives the identical block. A file reference, conversation handle, unknown encrypted-item extension, or independent owner keeps the operation bound.

Existing durable full-resend quota recovery projects a proven stored transcript; it remains separate from this unchanged-body exception. Routed files use typed pre-dispatch evidence and operation-wide finalization ownership. Hard continuity owners can remain admitted during transient backoff while caps and persistent availability still apply.

Local isolated SQLite and controlled adapter results do not establish live provider portability, PostgreSQL/MySQL/distributed runtime, publication, cloud gates, or production health.
